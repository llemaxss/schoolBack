# Стиль кода

## Форматирование

- Отступ - 2 пробела. Пустые строки внутри классов и методов тоже содержат отступ.
- Внутри класса оставлять 3 пустые строки: после `{` и `}` а так же перед `}`.
- Цепочка вызовов: каждый следующий `.метод(...)` на новой строке.
Если у вызова есть аргумент-выражение,
аргументы переносятся на отдельные строки,
закрывающая скобка тоже на отдельной строке:

```java
mockMvc.perform(
  post(UserController.URL)
    .header(
      HttpHeaders.AUTHORIZATION,
      adminBearerToken()
    )
)
  .andExpect(
    status()
      .isCreated()
  );
```

- Порядок методов в классах и интерфейсах: сначала `get`-методы, затем `create`, `update`, `delete`, потом остальные (например, `activate/deactivate`), приватные в конце.
- Константы в `enum` не сортируем по алфавиту: группируем по смыслу (например, `Permission` по сущностям и по CRUD).

## Вложенность вызовов

Максимум два уровня вложенности: `a(b(c))` - допустимо, `a(b(c(d)))` - нет.
Всю вложенность вынести в переменные или в приватные методы.
Лямбды с несколькими действиями тоже выносим в методы.

```java
// непраивльно
return new FieldError(name, findCode(error(result)), message(error(result)));

// правильно
String code = findCode(error);
String message = error.getDefaultMessage();

return new FieldError(name, code, message);
```

Могут быть исключения, если при этом не рушится читаемость кода.

## Названия методов: `get` и `find`

- `getX` - **"верни или упади"**: всегда возвращает объект либо бросает исключение (`CommonException` с `ErrorCode`). Никогда не возвращает `null`.
- `findX` - **"найди или верни null"**: возвращает `Optional<X>`. Пустой `Optional` означает "не найдено". Сам `null` метод не возвращает.
- `null` не должен быть в возвращаемых значениях.
Исключение: переопределяемые методы сторонних API, у которых контракт требует `null`.
- Derived-методы репозиториев (`findByUsername` и т.п.) тоже возвращают `Optional`.

## Аннотации `null`

- Параметр **без аннотации** означает "может быть `null`". `@Nullable` на параметрах не пишем.
- Если `null` недопустим, указываем `@NotNull`, а для `String` - `@NotBlank`. То же для возвращаемых значений: `@NotNull` над методом, `@NotBlank` для строки.
- `@Nullable` над методом допустимо только там, где вернуть `Optional` нельзя (переопределение стороннего API). В остальных случаях используем `Optional`.

## Валидация моделей запроса

В моделях используем только `@NotNull`, `@NotBlank`.
Остальные аннотации-валидаций (`@Size`, `@Min`, `@Max` и т.п.) не пишем.
Специфичные форматы (например, номер документа с точным числом знаков) проверяем в сервисе.

## Тесты

- URL берём из констант контроллеров (`UserController.URL`), а не собираем строкой.
- Коды ошибок сравниваем через enum: `ErrorCode.X.getId()`, без строковых литералов.
- Внутри разбиваем на блоки через внтуренние классы (аннотация `@Nested`). Оснонвые блоки: `Create\Update\Delete\Other`.
- Каждый блок теста оборачивать в комментарий `//region <name> //endregion <name>` для удобства чтения и навигации по коду.
