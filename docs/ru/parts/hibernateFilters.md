# Hibernate filters

(`_common/hibernateFilter`, `user/hibernateFilter`)

Фильтрация запросов на уровне Hibernate. Два фильтра:
- **soft-delete** - по колонке `delete_ts`, действует на все сущности (`CommonEntity`);
- **active users** - по колонке `is_active`, действует только на `User`.

## Как это работает

1. Каждый фильтр объявлен через `@FilterDef` в `package-info.java` (общие в `_common/hibernateFilter`, пользовательские в `user/hibernateFilter`) с признаком `autoEnabled = true`.
2. У параметра фильтра указан `resolver` - класс `Supplier`, который возвращает значение по умолчанию.
3. Hibernate сам включает такие фильтры при создании любой сессии.
4. Значение параметра берётся в таком порядке: сначала то, что поставили явно, потом значение из `resolver`.

В результате по умолчанию удалённые записи и неактивные пользователи не видны нигде: ни в веб-запросах, ни в тестах репозиториев, ни в фоновых задачах.

## Как менять фильтры из кода

Только через `component/HibernateFilterManager`. Для каждого фильтра есть три метода, и каждый принимает код (`Supplier`), который надо выполнить.

```java
Object result = hibernateFilterManager.executeXXX(() -> {
  return someFunction(params);
});
```

Правила:
- Включить или выключить фильтр «насовсем» нельзя. Фильтр меняется только на время выполнения переданного кода, после него (даже если код выбросил исключение) возвращается состояние, которое было до вызова.
Поэтому вложенные вызовы работают правильно: внутренний возвращает фильтр в состояние внешнего.
- Оборачивайте **минимальный** кусок кода (обычно один вызов репозитория). Всё, что вызывается внутри (в том числе другие сервисы), тоже увидит изменённый фильтр.
- Менеджер работает только внутри транзакции. Вне транзакции Spring выдаёт временную сессию, и изменения теряются.
- Чтобы вернуть прежнее значение параметра, менеджер читает его через внутренний класс Hibernate `FilterImpl`.

## Чего фильтры не касаются

Hibernate не применяет фильтры к прямой загрузке по первичному ключу (`em.find`, `getReferenceById`, ленивые связи `@ManyToOne`), а также к нативным запросам. Поэтому:
- `CommonRepositoryImpl.findById` переопределён и идёт через запрос (`findOne(Specification)`), чтобы фильтры работали.
- В нативных запросах условия по `delete_ts` и `is_active` пишутся вручную.
- Фильтры действуют только там, где на сущности или связи висит `@Filter(...)` - смотрите `CommonEntity`, `User`.

## Как добавить новый фильтр

1. Константы (имя, имя параметра, SQL-условие) - в `util/*HibernateFilterConstants` нужного модуля.
2. Класс `Supplier<Boolean>` со значением по умолчанию.
3. `@FilterDef` в `package-info.java` с `resolver = ...` и `autoEnabled = true`.
4. `@Filter(name = ...)` на сущности (или связи).
5. Три метода `execute...` в `HibernateFilterManager` (по образцу существующих).
